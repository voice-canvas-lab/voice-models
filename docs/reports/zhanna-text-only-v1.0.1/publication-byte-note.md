# Изменение байтов при публикации — 12 ноября 2026 года

Из `scripts/input_validation.py` удалены только лишние пустые строки в конце файла. Оставлен один завершающий CRLF; логика, пробелы внутри строк и все остальные байты сохранены. Размер уменьшился с 4497 до 4493 байт: удалены два завершающих CRLF после уже существовавшего перевода строки.

| Состояние input_validation.py | SHA256 |
|---|---|
| Исторический снимок эксперимента | `44389cc0006369dabdab79aa991d5a65ceea394495035a602313a0f6154847c1` |
| Публикуемая версия после удаления пустых строк | `e171614b63118fec07d210d752abbdd6c6b5aee923db3f430588571efed549e7` |

Причина — ошибка staged whitespace-check `new blank line at EOF`. Это изменение оформления при публикации, не изменение валидации или эксперимента. Старые freeze и результаты не обновлялись: они продолжают описывать прежний точный снимок. Поэтому SHA256 опубликованного input_validation.py отличается от указанного в исторических freeze; это ожидаемое и явно задокументированное различие.

В `docs/experiments/legacy-asr-pilots.md` аналогично удалён только один лишний завершающий CRLF (20438 → 20436 байт), оставлен один перевод строки:

- старый SHA256: `44e2e84611e0bc45ef4ffc40e8fedfc0030330e2054e5a885ea260b5a328eeca`;
- новый SHA256: `e63fdf543780952e8842fd4aa985e2a43c44fe84fceba15a428af119fff4d39c`.

Новые TTS/ASR-прогоны не выполнялись. Исходные данные, произношение, гипотезы, метрики и веса моделей не изменялись. Для сохранённых CRLF staged-проверка использует `cr-at-eol`, сохраняя проверки `blank-at-eol`, `blank-at-eof` и `space-before-tab`.
