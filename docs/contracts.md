## Контракты входных данных

Каждый контракт описан в отдельном разделе с полями и примером. Новые контракты добавляются следующими разделами.


### 1. `actions` — доступные действия

Массив описаний действий. Каждое действие содержит:

- `action_id`: `string` — уникальный идентификатор внутри переданного списка;
- `description`: `string` — описание смысла действия и его отличий от похожих действий;
- `parameters`: объект JSON Schema, описывающий аргументы.

Структура `parameters`:

- `type: "object"`;
- `properties` — словарь параметров;
- `required` — список обязательных параметров;
- `additionalProperties: false`.

Для каждого параметра обязательны:

- `type` — тип значения;
- `description` — смысл параметра.

При ограниченном наборе значений добавляется `enum`. Значения должны иметь понятное модели описание, особенно если используются технические обозначения.

Набор действий и названия параметров могут меняться между запросами. Модель выбирает действие по описанию, а не по фиксированному списку классов.

Пример:

```json
[
  {
    "action_id": "rename",
    "description": "Изменить название существующего объекта, сохранив его содержимое и расположение. Объект может быть указан явно или определяться через текущее выделение.",
    "parameters": {
      "type": "object",
      "properties": {
        "object_type": {
          "type": "string",
          "description": "Тип переименовываемого объекта: file — файл, folder — папка, document — документ, note — заметка.",
          "enum": ["file", "folder", "document", "note"]
        },
        "old_name": {
          "type": "string",
          "description": "Текущее название объекта, который нужно переименовать. Может быть получено из контекста для выделенного объекта."
        },
        "new_name": {
          "type": "string",
          "description": "Новое название, которое пользователь хочет присвоить объекту."
        }
      },
      "required": ["object_type", "old_name", "new_name"],
      "additionalProperties": false
    }
  }
]
```

### 2. `context` — состояние приложения

Объект с полями:

- `objects`: массив доступных объектов;
- `selected_object_ids`: массив идентификаторов выделенных объектов.

Каждый объект в `objects` содержит:

- `object_id`: `string` — уникальный идентификатор;
- `object_type`: `string` — тип объекта;
- `name`: `string` — название;
- `attributes`: необязательный объект с дополнительными свойствами.

Контекст фиксируется для конкретного высказывания. Все ID из `selected_object_ids` должны присутствовать в `objects`.

Если контекст отсутствует, передаются пустые массивы. История действий и координаты курсора в первую версию не входят.

Пример:

```json
{
  "objects": [
    {
      "object_id": "folder_17",
      "object_type": "folder",
      "name": "Черновики",
      "attributes": {
        "color": "blue"
      }
    }
  ],
  "selected_object_ids": ["folder_17"]
}
```

Пример пустого контекста:

```json
{
  "objects": [],
  "selected_object_ids": []
}
```

### 3. ASR output

Обязательные поля:

- `utterance_id`: `string` — уникальный идентификатор высказывания, используемый для связи запроса с результатом;
- `text`: `string` — окончательная расшифровка высказывания на русском языке.

Внутренний формат и способ работы ASR не ограничиваются. Перед передачей результата в `text → actions` он приводится к этому контракту.

Пример:
```json
{
  "utterance_id": "utterance_001",
  "text": "переименуй выделенную папку в Материалы"
}
```
