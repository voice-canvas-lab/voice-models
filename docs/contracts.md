## Контракты входных данных

Каждый контракт описан в отдельном разделе с полями и примером. Новые контракты добавляются следующими разделами.


### 1. `actions` — доступные действия

Массив описаний действий. Каталог хранится в `actions.jsonl`: одна строка — одно описание действия. При передаче в модель эти описания собираются в массив `actions`.

Каждое действие содержит:

- `action_id`: `string` — уникальный идентификатор внутри переданного списка;
- `description`: `string` — описание смысла действия и его отличий от похожих действий;
- `parameters`: объект JSON Schema, описывающий аргументы.

Структура `parameters`:

- `type: "object"`;
- `properties` — словарь параметров;
- `required` — список обязательных параметров;
- `additionalProperties: false`.

Для каждого параметра обязательны:

- `type` — тип значения;
- `description` — смысл параметра.

При ограниченном наборе значений добавляется `enum`. Значения должны иметь понятное модели описание, особенно если используются технические обозначения.

Набор действий и названия параметров могут меняться между запросами. Модель выбирает действие по описанию, а не по фиксированному списку классов.

Пример:

```json
[
  {
    "action_id": "rename",
    "description": "Изменить название существующего объекта, сохранив его содержимое и расположение. Объект может быть указан явно или определяться через текущее выделение.",
    "parameters": {
      "type": "object",
      "properties": {
        "object_type": {
          "type": "string",
          "description": "Тип переименовываемого объекта: file — файл, folder — папка, document — документ, note — заметка.",
          "enum": ["file", "folder", "document", "note"]
        },
        "old_name": {
          "type": "string",
          "description": "Текущее название объекта, который нужно переименовать. Может быть получено из контекста для выделенного объекта."
        },
        "new_name": {
          "type": "string",
          "description": "Новое название, которое пользователь хочет присвоить объекту."
        }
      },
      "required": ["object_type", "old_name", "new_name"],
      "additionalProperties": false
    }
  }
]
```

### 2. `context` — состояние приложения

Объект с полями:

- `objects`: массив доступных объектов;
- `selected_object_ids`: массив идентификаторов выделенных объектов.

Каждый объект в `objects` содержит:

- `object_id`: `string` — уникальный идентификатор;
- `object_type`: `string` — тип объекта;
- `name`: `string` — название;
- `attributes`: необязательный объект с дополнительными свойствами.

Контекст фиксируется для конкретного высказывания. Все ID из `selected_object_ids` должны присутствовать в `objects`.

В синтетическом датасете контекст генерируется вместе с текстовым примером и сохраняется в его составе. Наличие реального приложения не требуется..

Если контекст отсутствует, передаются пустые массивы. История действий и координаты курсора в первую версию не входят.

Пример:

```json
{
  "objects": [
    {
      "object_id": "folder_17",
      "object_type": "folder",
      "name": "Черновики",
      "attributes": {
        "color": "blue"
      }
    }
  ],
  "selected_object_ids": ["folder_17"]
}
```

Пример пустого контекста:

```json
{
  "objects": [],
  "selected_object_ids": []
}
```

### 3. ASR output

Формат результата распознавания для экспериментов с датасетом.

Обязательные поля:

- `sample_id`: `string` — идентификатор исходного примера, объединяющего текст команды, контекст и эталонную разметку;
- `audio_id`: `string` — идентификатор конкретной аудиозаписи;
- `text`: `string` — окончательная расшифровка высказывания на русском языке, полученная от ASR.

У одного примера могут быть разные аудиоверсии: голоса, настройки синтеза и аугментации. Они сохраняют одинаковый `sample_id`, но получают разные `audio_id`. Одинаковый текст с разными контекстами может относиться к разным примерам.

Адаптер ASR переносит оба идентификатора из метаданных входной записи. Сама модель их не генерирует. Для одной записи идентификаторы сохраняются при сравнении разных ASR; модель и настройки запуска фиксируются отдельно в результатах эксперимента.

Вместо `text_id` используется `sample_id`. Отдельный `utterance_id` в этом контракте не используется.

Внутренний формат и способ работы ASR не ограничиваются. Перед передачей результата в `text → actions` он приводится к этому контракту.

Пример:

```json
{
  "sample_id": "sample_001",
  "audio_id": "audio_001",
  "text": "переименуй выделенную папку в Материалы"
}
```

### 4. Хранение датасета и связи между файлами

Текстовые примеры и аудиозаписи хранятся отдельно и связываются идентификаторами.

В каждом JSONL-файле одна строка содержит один JSON-объект.

**`actions.jsonl` — каталог действий.** Одна строка содержит:

- `action_id`: `string` — уникальный идентификатор действия в каталоге;
- `description`: `string` — описание смысла действия;
- `parameters`: объект JSON Schema — схема аргументов.

Полная структура действия и пример описаны в разделе 1.

**`samples.jsonl` — размеченные текстовые примеры.** Одна строка содержит:

- `sample_id`: `string` — уникальный идентификатор примера;
- `text`: `string` — исходная команда пользователя, также используемая как эталонная расшифровка для ASR;
- `context`: объект — состояние по контракту из раздела 2; при отсутствии контекста передаются пустые `objects` и `selected_object_ids`;
- `available_action_ids`: массив строк — идентификаторы доступных для этого примера действий из `actions.jsonl`;
- `action_id`: `string` или `null` — эталонное действие; `null`, если единственное правильное действие не определено;
- `args`: объект — эталонные аргументы, где ключи соответствуют именам параметров действия; если аргументы не определены, передаётся `{}`;

**`audio_manifest.jsonl` — описание аудиозаписей.** Обязательные поля одной строки:

- `audio_id`: `string` — уникальный идентификатор аудиозаписи;
- `sample_id`: `string` — ссылка на исходный пример в `samples.jsonl`;
- `path`: `string` — путь к аудиофайлу относительно корня датасета.

Дополнительные метаданные:

- `voice`: `string` — идентификатор голоса TTS;
- `duration_sec`: `number` — длительность в секундах;
- `sample_rate`: `integer` — частота дискретизации в герцах;
- `augmentations`: массив объектов — применённые аугментации и их настройки; для чистой записи — пустой массив.

Аудиофайлы хранятся отдельно. Эталонный текст и контекст берутся из `samples.jsonl` по `sample_id`. Все аудиоверсии примера наследуют его `split`; близкие примеры с одним `group_id` также должны находиться в одной выборке.

Связи между записями:

- Одному `action_id` может соответствовать несколько текстовых примеров.
- Одному `sample_id` может соответствовать несколько аудиозаписей с разными `audio_id`.
- Каждый `audio_id` уникален в датасете, а его `sample_id` ссылается на существующий пример в `samples.jsonl`.

`sample_id` обозначает текстовый пример вместе с контекстом и разметкой. Одинаковый текст с разными контекстами может относиться к разным примерам.
